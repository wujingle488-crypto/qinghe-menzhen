# 第 1 章 需求分析

## 1.1 项目背景

基层科普与线上自助问诊需求增长，但通用聊天模型存在「胡编药名、忽略危急症状」等风险。本课程小组以「类蚂蚁阿福」体验为目标，建设**青禾门诊智能问诊系统**：在教学演示场景下，完成症状采集、知识检索增强生成、安全门禁与就诊卡辅助，形成可运行、可讲解、可测试的软件系统，而非一次性脚本。

系统明确声明：**不替代面诊，不做真实处方与医保结算**。

## 1.2 问题陈述

| 编号 | 问题 | 若不解决的后果 |
| --- | --- | --- |
| P1 | 用户不会一次说清病情 | 无法形成可用的参考建议 |
| P2 | 大模型可能编造药品与剂量 | 演示也不安全、不可信 |
| P3 | 胸痛等危急情况若继续「开方案」 | 违背安全底线 |
| P4 | 知识与会话无沉淀 | 无法体现系统级工作量 |
| P5 | 组件（模型/检索）可能宕机 | 演示中断、体验差 |

## 1.3 建设目标

1. 提供完整问诊主流程：开会话 → 多轮对话 → 参考诊断/处理建议 → 历史可回看。  
2. 知识有据：回答前经 RAG 检索，并展示出处线索。  
3. 安全可控：红旗拦截 + 药品白名单，门禁不可关闭。  
4. 系统可降级：模型或检索不可用时仍可演示且不崩溃。  
5. 具备就诊卡、知识库浏览/补充、语音与图片辅助输入等周边能力，体现「软件系统」体量。

## 1.4 用户角色与用例

### 1.4.1 角色

| 角色 | 说明 |
| --- | --- |
| 演示患者 | 使用问诊页描述不适、查看建议、管理历史与就诊卡 |
| 运营 / 医学编辑（演示） | 浏览与补充知识库文章 |
| 答辩评委 / 观众 | 通过演示与链路理解系统如何工作 |

### 1.4.2 主要用例

| 用例 ID | 名称 | 参与者 | 简述 |
| --- | --- | --- | --- |
| UC-01 | 开启问诊会话 | 患者 | 创建新会话或继续历史会话 |
| UC-02 | 多轮症状描述 | 患者 | 文字 / 语音 / 图片描述不适 |
| UC-03 | 获取参考建议 | 患者 | 得到可能诊断、处理建议、库内用药参考 |
| UC-04 | 危急拦截 | 系统 | 红旗症状仅劝急诊，不开药 |
| UC-05 | 就诊卡管理 | 患者 | 新建、编辑多张就诊卡并关联问诊 |
| UC-06 | 历史对话管理 | 患者 | 打开、重命名、删除、多选删除 |
| UC-07 | 知识库浏览与补充 | 运营 | 查看科普文章、补充条目 |
| UC-08 | 联网补充（可选） | 患者 | 开启后允许检索外网科普片段（仍过门禁） |

### 1.4.3 用例关系（文字）

```text
患者 ──UC-01──► 会话
  │
  ├──UC-02──► 输入（文本/语音/图）──► UC-03 建议卡片
  │                              └──► UC-04 红旗出口
  ├──UC-05──► 就诊卡 ──关联──► 问诊上下文
  └──UC-06──► 历史列表

运营 ──UC-07──► 知识库 ──供给──► RAG
```

### 1.5.2 安全与知识

| 需求 ID | 描述 | 优先级 |

## 1.6 非功能需求

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-1 | 可用性 | 必开组件：MySQL + 后端 + 前端；ES/向量/图谱可缺席降级 |
| NFR-2 | 安全表述 | 界面与卡片含「教学参考、非确诊」类声明 |
| NFR-3 | 响应 | 流式超时放宽至约 120s，适配看图与模型 |
| NFR-4 | 兼容 | 桌面宽屏侧栏 + 窄屏抽屉；现代浏览器 |
| NFR-5 | 可维护 | 后端 Java 模块化；前端 TypeScript；关键路径有单测 |
| NFR-6 | 容错 | 空输入拒绝；过期会话号自动重建；错误信息不直接抛原始 JSON |

## 1.7 范围边界

### 范围内

- 多轮智能问诊、RAG 增强回答、红旗与药白名单门禁  
- 就诊卡、历史会话管理、知识库浏览/补充  
- 语音听写、症状图片观察  
- 课堂演示剧本与链路可解释性  

### 范围外

- 淘宝式商城、购物车、支付、商家后台  
- 真实互联网医院接诊、医保、影像诊断  
- 模型自由编造药名并绕过白名单  
- 声称「已确诊」「电子处方已生效」  

## 1.8 成功标准（验收口径）

1. 至少三条演示剧本可复现：普通上感出方案、过敏含禁忌提示、红旗只急诊。  
2. 关掉部分检索组件或模型时，系统可降级演示且不崩溃。  
3. 展示药品均可在白名单中查到，并尽量带出处。  
4. 报告能说清：主流程、检索架构、降级阶梯、安全门禁。  
5. 非合理输入（空内容、过期会话、红旗否定句等）有明确处理策略。
