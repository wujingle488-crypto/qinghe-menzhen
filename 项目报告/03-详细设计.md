# 第 3 章 详细设计

## 3.1 问诊编排详细设计

### 3.1.1 类职责

| 类 / 组件 | 职责 |
| --- | --- |
| `ConsultController` | REST/SSE 入口；会话 CRUD、消息、上下文、中断恢复 |
| `ConsultOrchestrator` | 一轮问诊任务编排与状态视图 |
| `ConsultWorkflow` / `ConsultSupport` | 图节点或步骤：摄入、检索、生成、门禁、记忆 |
| `ConsultHistoryService` | 历史列表标题、删除、重命名、批量删除 |
| `RagFacade` | 统一检索入口，屏蔽底层索引差异 |
| `SafetyGate` | 红旗与药品校验；否定语解除 |

### 3.1.2 一轮消息时序

```text
前端                Controller           Orchestrator          RAG/LLM/门禁
 |  POST messages(SSE) |                    |                    |
 |-------------------->| 校验会话           |                    |
 |                     |------------------->|                    |
 |                     |                    |--红旗预检--------->|
 |                     |                    |--需要则 retrieve-->|
 |  event:retrieving   |<-------------------|<--hits-------------|
 |  event:generating   |<-------------------|--LLM 起草---------|
 |                     |                    |--SafetyGate-------|
 |  event:result(card) |<-------------------|<--通过/改写--------|
 |  complete           |                    |                    |
```

### 3.1.3 结果卡片字段

| 字段 | 含义 |
| --- | --- |
| `diagnoses` | 可能诊断（参考） |
| `plan` | 处理建议 |
| `drugs` | 白名单内用药参考 |
| `evidences` | RAG 命中出处 |
| `redFlag` | 是否危急出口 |
| `degraded` | 是否降级模式 |
| `disclaimer` | 教学免责声明 |
| `memory` / `chronicCaution` | 记忆与慢病提示（若有） |

## 3.2 安全门禁详细设计

### 3.2.1 红旗策略

1. 扫描用户文本中的危急模式（胸痛、冷汗、大出血、叫不醒等）。  
2. 若同句或近邻出现否定解除语（「不存在了」「没有了」「没了」等），则该红旗解除。  
3. 「和 / 与」连接的并列症状可一并解除。  
4. 命中且未解除：直接返回急诊建议，**不生成药品**。  

### 3.2.2 药白名单策略

1. LLM 草稿中的药品名与 `med_drug`（或等价白名单）比对。  
2. 未命中：剔除或改写为就医建议。  
3. 用法/禁忌优先采用库内文案，禁止模型自由剂量发挥。  

## 3.3 RAG 检索详细设计

### 3.3.1 检索通道（可配置）

| 通道 | 作用 | 关闭时 |
| --- | --- | --- |
| 向量（如 Chroma） | 语义相近科普段 | 走关键词/图谱/底账 |
| ES | 药名、标准症状、红旗词精确匹配 | 走向量/底账 |
| 图谱（Neo4j） | 病-症-药关系补充 | 忽略图谱命中 |
| MySQL 底账 | 最终兜底与元数据 | 核心数据仍需可用 |

### 3.3.2 融合

多路命中经 RRF（或等价融合）排序后截取 Top-K，拼入 Prompt。对 LLM 而言始终是一次「检索工具」调用。

## 3.4 会话与历史详细设计

### 3.4.1 会话实体要点

- `cs_session`：买家、店铺名（门诊智能助手）、状态、更新时间。  
- `title`：用户自定义标题；为空时用首条用户消息截断生成展示标题。  

### 3.4.2 历史操作

| 操作 | 接口 | 行为 |
| --- | --- | --- |
| 列表 | `GET /sessions` | 按更新时间倒序 |
| 重命名 | `PATCH /sessions/{id}` `{title}` | 校验非空，最长约 40 字 |
| 删除 | `DELETE /sessions/{id}` | 清消息、任务、痕迹、会话级记忆 |
| 多选删除 | `DELETE /sessions` `{ids:[]}` | 循环安全删除 |

前端侧栏：三点菜单 → 重命名 / 多选 / 删除；多选模式底部条批量删除。

## 3.5 就诊卡详细设计

| 能力 | 设计要点 |
| --- | --- |
| 多卡 | 同一 `user_id` 允许多行；启动修复历史唯一索引 |
| 字段 | 姓名、基础体征、过敏史、手术史、家族史等（演示级） |
| 关联问诊 | `PUT .../context` 写入 `profileId` / `profileLinked` |
| 注入 | 问诊摘要简报进入 Prompt，**不做诊断** |
| 回写 | 问诊结束后可按策略更新档案摘要 |

## 3.6 多媒体详细设计

| 能力 | 约束 |
| --- | --- |
| 图片 | jpeg/png/gif/webp，≤8MB；存本地；视觉模型只描述可见体征 |
| 语音 | 浏览器采集 16kHz WAV；本机听写；结果填输入框，不自动发送 |
| 合成发送 | `text` + `imageIds`；二者皆空拒绝 |

## 3.7 前端页面详细设计

| 页面 | 关键组件 / 行为 |
| --- | --- |
| 问诊 | `ConsultPage`：侧栏历史、SSE 对话、欢迎卡、输入区、就诊卡抽屉 |
| 就诊卡 | `ProfilePage`：表单编辑、多卡列表、跳转问诊 |

响应式：宽度 <800px 时历史侧栏改为抽屉遮罩。

## 3.8 异常与非合理输入处理设计

| 输入 / 场景 | 期望行为 |
| --- | --- |
| 文本与图片皆空 | 400/业务错：提示先描述或上传 |
| localStorage 会话已删 | 识别「会话不存在」，清本地号并重建后重发 |
| 红旗肯定句 | 急诊出口，无 drugs |
| 红旗否定句 | 解除后继续常规问诊 |
| 模型/检索失败 | `degraded` 提示，安全收尾，不 500 |
| 超大图片 | 上传拒绝 |
| 重命名空标题 | 拒绝，提示不能为空 |
