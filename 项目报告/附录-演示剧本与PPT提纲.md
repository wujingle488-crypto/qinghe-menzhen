# 附录 A 课堂演示剧本

> 建议总时长 8～12 分钟：演示 6～8 分钟 + 提问。

## 剧本 1｜普通上感（展示主链路）

1. 打开系统，介绍「青禾门诊 · 教学参考」。  
2. 点击「开启新对话」。  
3. 输入：「喉咙痛，低烧两天」。  
4. 若系统追问，简短补充：不发烧很高、无胸痛。  
5. **讲解点**：LLM 理解 → RAG 取知识 → 门禁校验 → 卡片含建议与免责声明。  

## 剧本 2｜红旗急诊（展示安全）

1. 新对话输入：「突然胸口疼，出冷汗」。  
2. **讲解点**：不诊断、不开药，只导向急诊；门禁不可关闭。  

## 剧本 3｜红旗否定（展示非合理/纠错输入）

1. 承接或新开后说明：用户更正病情。  
2. 输入含「胸口疼……不存在了，其实是嗓子疼」。  
3. **讲解点**：系统能解除误触发红旗，体现输入鲁棒性。  

## 剧本 4｜就诊卡 + 历史（展示系统完整性）

1. 打开就诊卡，展示多卡 / 关联。  
2. 回到问诊，打开历史三点菜单：重命名或说明多选删除。  
3. **讲解点**：这是完整软件系统能力，不只是「聊一句」。  

## 可选加分项

- 上传一张皮疹/喉咙相关图片，说明「只观察体征，仍过门禁」。  
- 关闭某检索组件后提问，展示降级不崩溃。

# 附录 B PPT 汇报提纲（建议 8～10 页）

| 页 | 标题 | 内容要点 |
| --- | --- | --- |
| 1 | 封面 | 项目名、组名、成员、课程 |
| 2 | 背景与目标 | 为什么做；教学演示定位 |
| 3 | 需求概览 | 角色、核心用例、范围边界 |
| 4 | 总体架构 | 前端 / agent-server / domain / MySQL / RAG / LLM |
| 5 | 主链路 | LLM → RAG → 门禁（强调串行） |
| 6 | 功能演示截图 | 问诊、红旗、就诊卡、历史菜单 |
| 7 | 安全与测试 | 白名单、红旗、用例与 Bug 修复 |
| 8 | 技术选型与分工 | 表格式一页说清 |
| 9 | 总结与展望 | 完成度、不足、改进 |
| 10 | Q&A | 预留 |

### 汇报表达建议

1. 先讲「用户故事」再讲技术，避免一上来堆组件名。  
2. 架构图只保留一条主箭头：问诊→检索→生成→门禁。  
3. 被问「是不是套壳 ChatGPT」时：回答有 RAG 依据、白名单、红旗、会话与就诊卡等系统能力。  
4. 被问「能不能真看病」时：明确教学演示、非诊疗。

# 附录 C 常见提问预案

| 可能提问 | 简要回答 |
| --- | --- |
| 为什么不用多 Agent？ | 问诊要共享上下文；多 Agent 贵且易丢槽位；本项目单 Agent + 工具 |
| ES 和向量是不是三套系统？ | 否，它们是 RAG 内部检索手段 |
| 药品怎么保证不乱开？ | Java 白名单门禁，模型草稿不过检不展示 |
| 没网 / 没模型怎么办？ | 降级路径；变笨但安全 |
| 工作量在哪里？ | 编排、门禁、RAG、就诊卡、历史、多媒体、UI、测试与文档 |
